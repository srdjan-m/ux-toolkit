UI/UX File Organization System

A two-level folder structure covering a global discipline workspace and per-project mirrors — consistent across all applications and task types, with Python tooling to scaffold projects and track file metadata.

System overview

Two levels share the same vocabulary: a global workspace holds cross-project knowledge, and each project mirrors the discipline folders inside its own stage subfolders.

The seven disciplines

Each discipline maps to one or more of your task types. Numbered prefixes enforce a logical sort order — discovery and code first, deliverables and diagrams last.

Key principles

Six rules that keep the system working as projects grow.

🔢
Numbered discipline order

01–07 prefixes sort folders by workflow, not alphabet. Dev and research come first because they inform everything that follows.

✂️
Only use what you need

Skip absent disciplines — don't create empty folders. A project without 3D work simply has no 06_3d.

🌐
Global = shared knowledge

Cross-project assets, libraries, and reference material only. Nothing project-specific lives in the global workspace.

_
Underscores for meta folders

_assets, _templates, _cache, and _archive sort below numbered folders so they're never in the way.

🐍
snake_case everywhere

No spaces in any folder or file name. snake_case keeps things CLI-friendly and consistent across macOS, Linux, and Windows — and the scaffolder now enforces it, rejecting invalid project and stage names.

🏁
production/ is sacred

Only final, approved, deliverable-ready files live here. If it's a WIP, it belongs in prototyping/ or design/.

Scaffolding script

Use new_project.py to create the full folder tree in one command. It runs on any machine with Python 3.9+, no dependencies required.

# Scaffold a new project with all defaults
python new_project.py my_app_name

# Only include disciplines you'll actually use
python new_project.py my_app_name --disciplines dev design illustration

# Create project in a specific directory
python new_project.py my_app_name --base-dir ~/projects

# Also bootstrap the global workspace (first time setup)
python new_project.py my_app_name --init-global

# Preview without touching the filesystem
python new_project.py my_app_name --dry-run

# Re-run safely: README.md / .gitignore are preserved unless you --force
python new_project.py my_app_name --force

# List available discipline keys
python new_project.py --list-disciplines

File metadata

Filenames tell you what a file is and what state it's in — but not who requested it or why it exists. add_meta.py records that context in a small sidecar file (<filename>.meta.md) that lives next to the asset and travels with it through Creative Cloud sync and version control.

🧷
Sidecars, not embedded data

Works for any file type — including binaries like .fig, .ai, .aep, and .blend — where embedded metadata or NTFS attributes wouldn't survive a copy or sync.

📇
One index, always current

The index command rolls every sidecar in a project into a readable INDEX.md and a sortable assets.csv — regenerated on demand, so it never drifts.

💬
Guided or scripted

Pass fields as flags for speed, or run with -i for an interactive prompt that fills in each field with the current value as the default.

# Attach / update metadata on a file
python add_meta.py set login_screen_v03-approved.fig \
    --requested-by product_team \
    --reason "Redesign login flow for accessibility audit AA-2026-07" \
    --status approved --tags login accessibility

# Guided mode — prompts for each field
python add_meta.py set login_screen_v03-approved.fig -i

# Read a file's metadata
python add_meta.py show login_screen_v03-approved.fig

# Rebuild INDEX.md + assets.csv from every sidecar in a project
python add_meta.py index my_app_name

The set fields

Option Records
--requested-byWho asked for the file
--reasonWhy it was created
--authorWho made it (defaults to the current OS user)
--statusValidated: wip · review · approved
--supersedesThe filename this version replaces
--tagsFree-form tags for grouping and search
--noteFree-text note stored in the sidecar body
-i, --interactivePrompt for every field instead of passing flags
